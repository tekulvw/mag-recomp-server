# Acquisition effect qualification and source components

The atomic callback adapter is still uninstalled. A complete authoritative
backend needs actual current world authority, complete native-equivalent overlap
queries and full entry/death/respawn/assignment consequences. The following
components implement bounded native behavior; they are not a live backend.

## Objective requests and assignment fields

`acquisition_objective_runtime::State::request` distinguishes current-state
guards from pending-target duplicate detection. Enable requires current0 and
requests1; Disable requires nonzero current and requests0; Lock requires current
other than9 and requests9. An identical pending target yields no request. These
requests do not commit current state or run OnChangeTargetStateId hooks.

Order records preserve nulls, source order and duplicates. Each resolved
objective carries its committed current state and the result of its qualified
attacker predicate for that squad. SecureAndHold inherits team16!=ownerTeam16;
other subclasses may override it. For attackers, Take matches current states
1,2,3,4,6 and Hold matches5,7,10,11,12; nonattacker roles reverse those groups.
Unknown order values, null objects and other states do not match. The admitted
replacement identity domain requires family0c80 and non-FFFF index; this is a
replacement restriction, not a claim about native candidate validation.

`Assignment::refresh` modifies an isolated candidate's primary/tag fields. The
native property gate value3, unresolved source spawnpoint or absent objective
list preserves both fields. The first valid normal objective supplies primary,
or FFFF when none; only a changed primary requests its setter. A manual full-ID
tag overrides FRAGO; otherwise the independent first-valid FRAGO supplies tag,
or FFFFFFFF. Tag setter handling remains distinct even with unchanged primary.
The backend must perform the complete live global sweep, source resolution,
setter consequences and replication; static initial catalogs do not prove these.

## Temporary volume setup

`acquisition_volume_geometry` reproduces float32 half extents, degree conversion
and the world-Y half-height center adjustment. Negative/zero extents are retained,
not repaired or claimed query-compatible. Native rotation convention is
Rz*Ry*Rx for column vectors, but no host trigonometric matrix is substituted for
the native SIMD path. Extreme/denormal/native arithmetic modes remain outside the
bounded private transform probes. No actual penetration query is implemented.

The pair-level raw-filter6 helper uses the supplied CURRENT row6 mask and the
target filter's low5-bit layer. Query system group0 means upper target filter bits
do not select a same-system-group exception. The initial layer mask is not a
proof that current runtime filters never change. Shape filters, margins,
complete body coverage, root identity/liveness and ordered pair collection remain
provider requirements. The existing actor AABB broad phase deduplicates and sorts
actors and cannot stand in for that provider.

## Lethal metadata is not a force-zero shortcut

`acquisition_damage_metadata` admits only the bound ExternalKinetic5/Crushed10
symbol pair. Negative character damage constructs a raw1000 HP ordinary damage
request, copies the native victim vector without normalization, uses the victim
as attacker, and sourceIndex/sourceObject=-1. A previously set invulnerability
bool is cleared for ApplyDamage and restored to canonical1 afterward; an initial
zero has no restore write. Dead checks, notifications, modifiers and armor still
apply. No constructor applies damage or proves the victim dies.

Negative ground damage supplies attackerFFFFFFFF and vaporize=true. The model's
separate dead guard and SetHealth(0,-1), later OnDeath, occupant handling, FSP
notifications and removal cannot be replaced by bunker-health logic. Mine damage
continues to mutate accumulation/detonation flag; explosion/replication/removal
belong to later qualified processing. Owner-update damage queues and ordinary
firearm death notifications also have incompatible timing/metadata for these
callbacks and are not substituted.

## Installation requirements

The source components do not implement the complete backend. Current missing
capabilities include the complete live collidable roster/local transforms/filter
state/generation-safe root mappings, full character mounted/kit/objective/scoring
consequences, vehicle update/occupant/vaporize behavior, mine radial effects and
removal, FSP immediate spawn allocation/replication, and entry/tag/stat authority.
Native entry depends on previous state and additional stats beyond the existing
reward variants. Complete structural instruction bridges are evidence, not proof
that all transitive consequences have been modeled.

Keep callback installation off until those requirements are implemented and
qualified. Initial-load objective qualification remains pre-MissionStart.
Releases remain manual after human live-match review.
