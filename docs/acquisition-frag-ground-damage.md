# Acquisition vehicle frag damage

An Acquisition gameplay configuration can supply `frag_ground_areas` as the path
to source-qualified damage-area rules. The option is absent/off for existing
profiles and is independent of hospital rockets and the Character blast boolean.
Direct Engine and registry startup require the current Structural/material world,
retail item authority, Ground policy, explicit vehicle sources and matching dynamic
body inputs before advertising this scope.

The maintained `tools/extraction/project-retail-acquisition-frag-ground-areas.py`
binds all nine role/faction variants to the original executable/archive, selected
chassis packs, current neutral template catalog, area thresholds and wheel proof.
Acquisition's type-3 APC, type-7 motor-pool and type-9 Escort sources remain distinct.
The native multi-pack chassis selector uses the qualified tag and exact pack hash;
it never treats a turret pack as the hull. Existing Ground/Helo projector defaults
retain their original unique-pack behavior.

At an authenticated ordinary frag fuse terminal, the planner uses the accepted
owner-event Character and Ground pose view. A positive overlap with either bound
chassis or wheel qualifies the operational vehicle. Area, radial attenuation and
one target-excluding layer-24 material ray use the current model origin and
orientation, rather than an individual root offset. The dose comes from the
item's vehicle channel with native zero armor reductions, classified area 1–6,
existing friendly scaling and current vehicle armor.

A vehicle receives one dose per terminal even if both roots overlap. This is an
explicit bounded replacement policy; native repeated-callback parity remains
unverified. Wheel-only eligibility is retained, and other vehicles' wheel cover
keeps its existing represented-world query behavior. No raw-layer guess or
hospital projectile-contact dependency identifies the wheel.

Field 18 carries type 10, classified location, encoded direction, authenticated
attacker and the explicit invalid source-word policy. The admitted projectile
identity remains in audit. The native vehicle source value and inherited export
remain unqualified; the source-word erratum does not change this policy.

The outer owner event records before installing motion, flight, damage or reliable
publication. Typed query failures record their denial while preserving legitimate
motion and terminal/Character handling. They never fall through to the legacy
incorrect damage calculation. The normal Ground critical/destruction, occupancy,
repair, reinforcement and respawn consumers handle the resulting health state.

Original-input projection and scripted Engine replay establish source behavior.
Native client behavior, exact physics/callback ordering and live-match acceptance
remain separate. The maintainer reviews the live match and cuts releases manually.
