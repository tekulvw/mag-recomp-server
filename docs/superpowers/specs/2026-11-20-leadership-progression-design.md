# Leadership experience and persistent advancement

Implement leadership points and rank progression through the existing committed gameplay reward outbox and Horizon character-store transaction. Rust captures the actual reservation-bound native role once when the existing terminal reward is created. Retail uses the role currently held at that calculation: Squad1, Platoon2 or OIC4; no command-time weighting or ever-held/highest-role substitution. A later replacement cannot inherit another character's frozen receipt.

Horizon loads the selected application's complete authored leadership award/threshold/creation tables. It selects the table row by frozen role and match outcome, truncates positive f32 awards, adds cumulative points and resolves rank using both inclusive point and ordinary-character-level requirements. Row0 is the default zero rank. Normal character creation and tracked ordinary XP updates use the same qualified resolver. Do not hardcode populated retail balance tables or apply prototype values to retail.

Use an optional terminal reward context `leadership:{role,baseline:{leadership_level,nominations,matches_since_last_command}}`. Horizon enables this context only when it advertises complete authored leadership settlement support at admission; absent support retains XP-only behavior. Absent context retains legacy receipt behavior; present data must be complete and valid only on a unit-one terminal kind. The baseline preserves the configured admission fallback only when no saved leadership row exists. Existing rows always win. Preserve nomination and command-recency values; their independent mutation paths are outside this task.

Persist optional unsigned cumulative LeadershipPoints with the existing saved record and expose it in native full records/admission. For historical persisted rows whose point balance was never tracked, begin the tracked point balance at zero without fabricated grants and retain their existing eligibility with an explicit private compatibility floor. Keep that floor until the native-resolved rank reaches it. Freshly materialized/new character records have no floor and follow the native function exactly. This is a migration policy, not an original game mechanic.

Settle leadership and ordinary XP in the same account/character/round finalization and immutable receipt. Persist stable acknowledgement snapshots, freeze context as duplicate facts, reject changed-context replay and different-ID replay after finalization, and reject overflow without partial mutation. Retain established uncertain-store-commit semantics. Return optional `leadership` (saved fields plus optional leadership_points) and optional match_leadership_points with progression acknowledgements. Rust updates current same-character snapshots, rank publication and stat7 after recording; old/out-of-order acknowledgements cannot regress tracked state or credit a replacement occupant. Deferred old-round receipts may refresh newer cumulative account state while leaving current match totals untouched; admission record reads and reserve serialize against settlement. Native live presentation remains a separate acceptance step.

Global constraints: freshly fetched source main, isolated public source branch; private checkpoints on main; source and synthetic tests public, original assets/data/native evidence private; no XERJ, game, services, accounts, deployment, release or released-gitlink changes. Releases remain manual. User autonomy permits implementation choices and checked source integration without routine approval prompts.
